# Event & memory schemas

Status: draft for architecture review · Feeds ADR-0003, ADR-0010 · Companion to `memory-model.md`

Canonical wire formats. TypeScript interfaces are the normative definition (Zod schemas in
`packages/core/src/schema/` will mirror them 1:1 in Phase 1 and are the enforcement point at every
boundary: adapter → engine, HTTP, MCP, CLI). All timestamps are ISO 8601 UTC. All IDs are UUIDv7.

---

## 1. The common event envelope

Every adapter (Claude Code, Codex, Cursor, Pi, OpenCode, file watcher, git watcher, CLI) translates
runtime-specific activity into this one envelope. The engine **never** knows about runtimes.

```ts
interface OnememoryEvent {
  id: string;                 // uuidv7, generated by adapter
  kind: EventKind;             // §2
  occurred_at: string;        // when it happened in the runtime
  ingested_at: string;        // when onememory accepted it
  source: EventSource;        // who emitted it
  scope: EventScope;          // where it belongs
  payload: EventPayload;     // kind-specific, discriminated union, §2
  content_hash: string;       // sha256 of canonical payload, §7
  redactions: Redaction[];    // secrets stripped during ingest, §7 (count + location only)
}

interface EventSource {
  runtime: 'claude-code' | 'codex' | 'cursor' | 'pi' | 'opencode' | 'mcp-client'
         | 'cli' | 'file-watcher' | 'git-watcher' | 'api' | 'webhook';
  adapter_version: string;    // semver of the adapter package
  instance_id?: string;       // e.g. workspace path hash, machine id — never a hostname if privacy mode
}

interface EventScope {
  project_id?: string;        // resolved from cwd / repo root; NULL = global
  session_id?: string;       // agent session, when the runtime exposes one
  agent_id?: string;         // e.g. "claude-code", "opus-plan", a bot name
  user_id?: string;          // resolved identity; NULL in single-user local mode
}

interface Redaction {
  kind: 'api-key' | 'password' | 'token' | 'private-key' | 'connection-string' | 'other';
  location: string;          // JSON path of the redacted field, e.g. "payload.content"
  length: number;            // length of removed secret (for audit), the secret is NEVER stored
}
```

Envelope rules:
- Adapters MUST NOT drop events because a field is unknown: unknown `kind`s are stored raw
  (`kind: 'raw.unknown'`) and ignored by extractors until a handler exists.
- Envelope validation is strict (Zod): a malformed event goes to the dead-letter log with the
  validation error, never crashes the pipeline, never blocks the agent runtime.

## 2. Event kinds and payloads

```ts
type EventKind =
  // conversations & agent work
  | 'conversation.message'
  | 'conversation.tool_call'
  | 'conversation.tool_result'
  // developer activity
  | 'terminal.output'
  | 'error.raised'
  | 'test.results'
  | 'file.changed'
  // git & review
  | 'git.commit'
  | 'pull_request'
  // documents
  | 'document.added'
  // explicit user intent (highest source authority)
  | 'explicit.remember'
  | 'explicit.forget'
  // session lifecycle
  | 'session.start'
  | 'session.end'
  // escape hatch
  | 'raw.unknown';
```

### Conversation

```ts
// conversation.message
{ role: 'user' | 'assistant';
  content: string;                // plain text; markdown preserved
  mentions?: string[];           // files/symbols @-mentioned
  summary?: string;              // adapter-provided one-liner, optional
}

// conversation.tool_call
{ tool: string;                 // e.g. "Read", "bash", "search"
  call_id: string;               // correlates call → result
  arguments_digest: string;     // ≤ 400 chars of the important args (paths, command)
}

// conversation.tool_result
{ call_id: string;
  ok: boolean;
  output_digest: string;        // ≤ 2000 chars, truncated with marker
  error?: { code?: string; message: string };
}
```

### Developer activity

```ts
// terminal.output
{ command: string; exit_code: number | null;
  output_digest: string;         // tail ≤ 2000 chars
  shell?: string; }

// error.raised
{ origin: 'terminal' | 'test' | 'build' | 'runtime' | 'tool';
  message: string;              // first line / error class
  context?: string;              // ≤ 500 chars of surrounding detail
  stack_digest?: string; }

// test.results
{ framework?: string; passed: number; failed: number; skipped?: number;
  failures?: { name: string; digest: string }[]; }   // ≤ 10 failures, each digest ≤ 300 chars

// file.changed
{ path: string;                  // repo-relative
  change: 'created' | 'modified' | 'deleted' | 'renamed';
  old_path?: string;
  blob_sha_before?: string; blob_sha_after?: string;
  lines_added?: number; lines_removed?: number; }
```

### Git & review

```ts
// git.commit
{ sha: string; message: string; author_name: string; // author EMAIL is NOT captured (privacy)
  files: string[];                // repo-relative paths, ≤ 500
  stats?: { files_changed: number; insertions: number; deletions: number };
  repo_fingerprint?: string; }    // § code-memory doc

// pull_request
{ number: number; title: string; state: 'opened' | 'merged' | 'closed';
  repo?: string;
  review_digest?: string; }       // ≤ 1000 chars of substantive review comments
```

### Documents & explicit intent

```ts
// document.added
{ path?: string; uri?: string;    // exactly one required
  mime: 'text/markdown' | 'text/plain' | 'application/pdf' | 'text/html'
      | 'application/json' | 'text/csv' | string;   // source code arrives as text/*
  title?: string;
  content_digest: string;          // ≤ 8000 chars extracted text
  full_text_ref?: string; }       // pointer to blob stored outside the event (documents only)

// explicit.remember — `onemem remember "…"` / `memory_store` MCP tool
{ content: string;
  type?: 'semantic' | 'procedural' | 'decision' | 'preference' | 'failure';
  importance?: number;            // user override
  tags?: string[];
  scope?: 'project' | 'user' | 'global'; }

// explicit.forget
{ memory_id: string; purge?: boolean; reason?: string; }

// session.start / session.end
{ started_at?: string; ended_at?: string;
  cwd: string; project_hint?: string;
  summary?: string; }             // session.end only; adapter- or agent-generated
```

## 3. Extraction output schema

The EXTRACT stage (LLM or heuristic) MUST emit this exact shape. Structured, schema-validated;
a retry with the validation error is cheaper than corrupting memory.

```ts
interface ExtractionResult {
  memories: ExtractedMemory[];
  working: WorkingCandidate[];      // session-scoped notes worth keeping temporarily
  session_summary?: string;         // ≤ 500 chars
  extraction_meta: {
    method: 'llm' | 'heuristic';
    model?: string;                 // e.g. "ollama/llama3.1", "openai/gpt-4o-mini"
    prompt_version: string;
  };
}

interface ExtractedMemory {
  type: 'episodic' | 'semantic_candidate' | 'procedural' | 'decision'
      | 'failure' | 'preference';
  content: string;                  // canonical, self-contained, ≤ 500 chars
  title?: string;                   // ≤ 80 chars
  subtype?: string;
  importance: number;               // 0–1
  confidence: number;               // 0–1
  entities: string[];               // mentioned entity names (resolved later)
  relationships?: Array<{ target: string; relation: RelationType }>;
  project?: string;                 // project hint, if derivable
  evidence: EvidenceSpan[];         // mandatory for durable; ≥ 1 span
  valid_from?: string; valid_until?: string;
  future_value_rationale?: string;  // one clause: why this is worth remembering (quality signal)
}

interface WorkingCandidate {
  kind: 'task' | 'hypothesis' | 'current_file' | 'current_error' | 'temp_decision' | 'open_question';
  content: string;                  // ≤ 300 chars
  session_id: string;
}

type RelationType =
  | 'related_to' | 'depends_on' | 'caused_by' | 'solved_by' | 'decided_by'
  | 'supersedes' | 'contradicts' | 'derived_from' | 'belongs_to' | 'used_by' | 'modifies';

interface EvidenceSpan {
  source_id: string;                // FK to sources (created at ingest)
  kind: 'message' | 'range' | 'commit' | 'line' | 'event';
  locator: string;                  // e.g. "session.jsonl:183", "commit:abc123", "lines 4-9"
  excerpt: string;                  // ≤ 200 chars
}
```

The extractor's first decision is the spec's gate: **does this have future value?** Anything the
extractor can't justify (no `future_value_rationale`, low importance) is discarded, not stored.
In fully-local no-LLM mode the heuristic extractor recognizes: explicit preference/decision
language, error+resolution pairs, recurring commands (procedure candidates), stack names, and
versioned facts. Lower recall than an LLM, zero external calls, correct shape.

## 4. Memory wire representation

What `GET /v1/memories/:id`, MCP `memory_get`, and CLI `onemem inspect` return:

```ts
interface MemoryRecord {
  id: string;
  type: 'episodic' | 'semantic' | 'procedural' | 'decision' | 'failure' | 'preference' | 'working';
  subtype?: string;
  title?: string;
  content: string;
  content_summary?: string;
  status: 'active' | 'stale' | 'superseded' | 'disputed' | 'archived';
  importance: number;
  confidence: number;
  access_count: number;
  last_accessed_at?: string;
  observed_at: string;
  valid_from: string; valid_until?: string;
  created_at: string; updated_at: string;
  superseded_by?: string;
  project_id?: string; user_id?: string; agent_id?: string;
  provenance: {
    source: { id: string; kind: string; uri?: string; title?: string };
    evidence: EvidenceSpan[];
    extraction: { method: string; model?: string; prompt_version: string };
    verified_at?: string;
  };
  entities: Array<{ id: string; name: string; kind: string }>;
  tags: string[];
  token_estimate: number;
  payload?: DecisionPayload | FailurePayload | SkillPayload;  // per type, §5
}
```

## 5. Typed payloads

```ts
// decisions — memories.type = 'decision'
interface DecisionPayload {
  title: string;
  decision: string;                 // what was decided
  alternatives: Array<{ option: string; why_rejected?: string }>;
  rationale: string;
  participants: string[];           // roles/names, never emails
  decided_at: string;
  status: 'proposed' | 'accepted' | 'superseded' | 'rejected';
  evidence: EvidenceSpan[];
}

// failures — memories.type = 'failure'
interface FailurePayload {
  problem: string;
  context: string;                  // environment, limits, versions
  root_cause?: string;
  solution?: string;                 // empty until solved
  verification?: string;            // how the fix was proven (command output digest, test result)
  status: 'open' | 'mitigated' | 'solved' | 'verified';
  first_seen_at: string; last_seen_at: string;
  occurrence_count: number;         // incremented on signature match
}

// skills — generated from verified procedures/failures
interface SkillPayload {
  name: string;                      // kebab-case, directory name
  description: string;
  version: string;                   // semver
  status: 'candidate' | 'verified' | 'promoted' | 'deprecated';
  source: { failure_ids: string[]; procedure_id?: string };
  verification: { evidence: EvidenceSpan[]; verified_at: string };
  path: string;                      // skills/<slug>/SKILL.md
  usage_count: number; success_rate?: number;
}
```

`SKILL.md` layout (written to `skills/<slug>/SKILL.md`, consumable by Claude Code / OpenCode
skills and by onememory's own agent-facing listing):

```markdown
---
name: cloud-run-permission-fix
description: Fix Cloud Run deploys failing on missing service-account permissions
version: 1.0.0
---

## When to use
[trigger conditions — matched against new failure signatures]

## Prerequisites
[required access/tools]

## Procedure
1. … (commands in fenced blocks)

## Validation
[how to prove it worked]

## Known failure modes
[what else goes wrong in this territory]
```

## 6. Retrieval request/response

`memory.search(query, max_tokens=1000)` — REST `POST /v1/memories/search`, MCP `memory_search`,
CLI `onemem search`. Token budget is the primary limit; memory count is secondary.

```ts
interface MemorySearchRequest {
  query: string;
  project_id?: string;               // default: caller's project
  max_tokens?: number;              // default 800 (hard ceiling for packed context)
  max_memories?: number;            // default 10, soft
  types?: MemoryType[];             // filter
  entities?: string[];              // entity filter
  as_of?: string;                   // point-in-time query (temporal mode)
  temporal_mode?: 'current' | 'historical';   // default current
  include?: Array<'stale' | 'superseded' | 'archived' | 'disputed'>;
  session_id?: string;              // includes working memory of that session only
  explain?: boolean;                // default false in prod, true in dev/CLI verbose
}

interface MemorySearchResponse {
  query_understanding: {
    intent: 'fact' | 'how_to' | 'decision' | 'failure' | 'preference' | 'history' | 'context';
    entities: Array<{ name: string; matched_id?: string }>;
    time_scope?: { from?: string; until?: string; mode: 'current' | 'historical' };
    keywords: string[];
  };
  memories: Array<{
    id: string; type: MemoryType;
    title?: string;
    summary: string;                 // packed representation (content_summary)
    content?: string;                // included only if budget allows and detail > summary
    relevance: number;               // 0–1 final
    explain: Array<{ factor: ScoreFactor; weight: number; detail: string }>;  // § explainability
    temporal: { valid_from: string; valid_until?: string; status: string };
    provenance: { source_kind: string; source_uri?: string; verified_at?: string };
    conflicts?: Array<{ memory_id: string; note: string }>;   // when disputed/contradicted
  }>;
  tokens: { budget: number; used: number; packing: 'summary' | 'content' | 'title-only' };
  warnings: string[];                // e.g. "embedding index degraded: lexical only",
                                     //      "2 disputed memories excluded by default"
}
```

Explainability factors (spec §33): `project_match`, `entity_match`, `semantic_similarity`,
`lexical_relevance`, `importance`, `confidence`, `recency`, `access_frequency`, `temporal_validity`,
`graph_proximity`, `type_affinity`. The `explain` array reconstructs the ranking in plain terms.

## 7. Canonicalization & hashing

- **Canonical JSON**: UTF-8, sorted keys, no insignificant whitespace, numbers as-is, no NaN.
- **`content_hash`** (event): sha256 of canonical payload JSON.
- **Memory `content_hash`**: sha256 of normalized content: NFC unicode, trimmed, whitespace
  collapsed to single spaces, lowercased. This is the exact-dedupe key.
- **Dedupe scope**: `(project_id, type, content_hash)` — same statement may be valid in different
  projects; user-scope memories use `user_id` instead.
- **Redaction invariant**: redaction records store kind + location + length only. The secret value
  never reaches the database, logs, or an LLM prompt.
- **Truncation policy**: digests carry explicit `+N more chars` markers so extraction can see it is
  working with truncated evidence.

## 8. Versioning & compatibility

- Schemas live in `packages/core/src/schema/` as Zod, exported as TypeScript types; every boundary
  validates through them.
- Breaking changes to the event envelope are not allowed after 1.0 — only additive optional fields
  (agents' adapters ship independently of the engine). The schema carries `schema_version`.
- Unknown-field tolerance is required at every boundary for forward compatibility.
