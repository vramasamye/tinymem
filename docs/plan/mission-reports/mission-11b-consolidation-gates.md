## 2. Wiring design (scope item 1)

`runConsolidation` is the callable entry; the harness calls it as-is (no pass cherry-picking, no
re-implemented orchestration — AGENTS.md rule 2). Ordering: extraction → fact resolution →
declared supersessions → automatic pass → probes. Declared supersessions run **first** and close
the loser's `valid_until`, so the contradiction pass's `temporalOverlap` can never re-detect a
declared pair — declared beats automatic by construction, and the temporal dataset's explicit chain
never fights the pass (that dataset does not opt in and is byte-identical).

Determinism: the pass runs with `now: () => new Date(dataset.now)` — the same fixed clock the
retrieval engine and every probe use. Fact keys resolve against the **pre-pass corpus snapshot**
(consolidation only changes status, never content/scope/type, so matchers stay valid even for
memories the pass supersedes or disputes); probes search the **post-pass** store, so losers are
superseded, tie sides are disputed, and all three are excluded from current answers — exactly what
`contradiction_accuracy` measures.

**Offline honesty (design constraint, not a limitation):** the harness wires no embedder and no
model router (the AGENTS.md rule 4 local-first default), so `runConsolidation`'s vector-gated passes
(derivation, near-duplicate merge) skip with the package's own degradation warning, recorded in the
dataset report and pinned by the gate test. The alternative — a hand-tuned lookup-table embedder to
force the vector passes to run — was rejected: it would make the metric measure the table, not the
engine. Consequence: `consolidation_quality`'s offline ceiling is ingest-time exact dedupe (the
`consolidation-repeats` paraphrase pair stays distinct). That is the honest measured value and the
gate sits at it.

**Decay + the fixed clock (scope item 1's warning):** fixtures are ≤ 100 s old against the 3600 s
`now`, so recency ≈ 1 and every fixture's prominence sits far above the 0.05 archive threshold
(measured: `archived: 0` on both opted-in datasets — pinned by the gate test, so a fixture or formula
regression that starts archiving young rows fails CI). No dataset intends archival; nothing is
archived. The full per-dataset summary is rendered in `baseline.md`.

## 3. Contradiction coverage (scope item 2)

Six groups, every one driven through real extraction and the real pass (contents below are the
actual extracted memory contents, not the raw prose):

| Group | Pair shape (observed_at, type, source, confidence) | Authority rule exercised | Result |
|---|---|---|---|
| `explicit-over-decision` | explicit.remember semantic `8081` (30 s, `semantic`, `explicit`, 0.95) vs conversation decision `8080` (40 s, `decision`, `conversation`, 0.85) | **explicit > decision**: the older explicit statement beats the newer decision | resolved — explicit wins |
| `decision-over-observation` | explicit decision `5432` (50 s, `decision`, `explicit`) vs explicit semantic `5433` (60 s, `semantic`, `explicit`) | **decision > newer**: both explicit, so the older decision beats the newer observation | resolved — decision wins |
| `newer-decision-wins` | conversation decision cap 20 (70 s) vs cap 50 (80 s), both user | **newer**: same class/source, later wins | resolved — 50 wins |
| `confidence-wins` | user `30 days` vs assistant `90 days`, both at 90 s, both `decision` | **confidence**: same class at the same instant; user 0.85 beats assistant 0.6 | resolved — 30 days wins |
| `full-tie-disputed` | two user decisions, both at 100 s, both 0.85 | **full tie**: both marked `disputed`, both excluded from current answers (`outcome: 'disputed'` — no expected fact, both sides forbidden) | resolved-as-tie — neither side returned |
| `database-dialect` (kept from M11a) | PostgreSQL/pgvector vs MySQL — same concept, different wording | none detectable: the attribute-template heuristic sees different templates | **unresolved** — the measured miss (see finding 1) |

Measured: 6 groups, 5 resolved, `accuracy 0.8333`, `authority_top1 3`, `silent_conflicts 1`. Every
group that the heuristic *can* detect resolves correctly end to end; the one miss is the cross-phrasing
pair, kept deliberately.

Fixture craft notes (why the pairs are detectable): the heuristic detector fires on same scope +
same template + differing scalars, so each pair's two extracted contents differ only in their
numbers ("`Decision: port 8080 for the API gateway`" vs "`…8081…`"). The rule-4 pair needs equal
`observed_at`, so both events sit at offset 90 in different sessions with different roles (role
drives extraction confidence: user 0.85, assistant 0.6). The tie pair sits at offset 100 in two
sessions with identical everything — the pass must tie, not pick. New fixture wordings avoid the
lexemes of the dataset's pre-existing retrieval query (`databas`/`decid`/`use`), so that query still
returns exactly the two database decisions — retrieval metrics are byte-identical (§5).

## 4. The gates (scope item 3)

| Metric | Pre-M14 (reported) | Post-M14 measured | Gate | Headroom | Rationale |
|---|---:|---:|---:|---:|---|
| `contradiction_accuracy` | 0.0000 (0/1) | **0.8333 (5/6)** | ≥ 0.8 | ~0.03 | the miss is the cross-phrasing detector gap (finding 1); any single passing group regressing drops to 4/6 = 0.6667 and fails |
| `consolidation_quality` | 0.3333 | **0.3333** | ≥ 0.3 | ~0.03 | the offline ceiling (finding 2); a dedupe regression (e.g. the exact-repeat group splitting) drops it to 0.1667 and fails |

Both thresholds sit one 0.05 metric step below the measured value, matching the existing gates'
headroom convention. Neither threshold was loosened to hide a weakness — both weaknesses are kept
visible: the cross-phrasing pair stays in the dataset and its silent conflict is pinned
(`silent_conflicts = 1`) in the gate test; the paraphrase pair stays unmerged and the offline
degradation warning is pinned in the gate test. The six pre-existing gates are unchanged
(temporal 1.0 / precision 0.7 / recall 0.9 / budget 1.0 / top-1 0.0 / distractor 0.2). `gates.test.ts`
keeps unit breach proofs for every gate including the two new ones; `harness.test.ts` proves the
live report fails once each new threshold is raised to 0.99.

## 6. Findings (scope item 4 — gate at the honest value)

1. **The attribute-template heuristic misses cross-phrasing contradictions** (the mission's
   anticipated weakness, now measured). "Decision: use PostgreSQL with pgvector as the only database
   dialect" vs "Decision: use MySQL for the primary datastore" contradict in meaning but produce
   different templates, so `contradictsHeuristically` never fires: both rows stay current and the
   probe surfaces a silent conflict. Kept in the dataset, gated honestly at 0.8 (not hidden by
   rephrasing the fixture to match the detector), and pinned by the gate test
   (`silent_conflicts = 1`). Fixing it needs the M14 follow-up **LLM conflict detector** (backlog
   "raised by M14" item 5); when it lands, `accuracy` → 6/6 = 1.0 and the gate should be raised with
   a fresh baseline — the gate test's pin makes that a conscious change.
2. **`consolidation_quality` is bounded offline by design.** With no embedder the vector-gated
   passes skip (recorded warnings), so the paraphrase pair stays distinct and quality stays at the
   exact-dedupe ceiling 0.3333. Gated at 0.3 with the degradation warning pinned in CI. Lifting it
   needs either the embedder tier wired into a benchmark profile (an M11b-backlog-tier benchmark
   variant with a local embedder, no network after model cache) or a lexical near-duplicate merge —
   both are engine-side decisions, not benchmark-side.
3. **`authority_top1` is 3/5 on resolved groups** (diagnostic, not gated): two probes rank a
   different-domain memory above the authority (e.g. "Port 5432 is the standard API port…" above the
   gateway-port fact under the "which port…" probe). The authority is present and the contradicted
   side absent — the accuracy contract holds; ranking within the returned set is retrieval's
   lexical-tie domain, not the contradiction gate's.
